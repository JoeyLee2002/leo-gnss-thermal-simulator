# 设备受约束标定使用说明

适用版本：0.4.3。

## 这个功能解决什么问题

用户先描述自己的设备，再用一部分遥测修正模型中不确定的参数，最后用未参与标定的遥测检查预测。
标定只允许在预先声明的设备范围内调整参数，不能为贴合温度曲线自动扩大范围。
软件保存原设备和标定设备两份配置，不覆盖原值，也不自动用标定值重新定义下一次的标称值。

软件能保证不越过输入范围，但不能保证用户输入的范围本身就是真实设备的范围。
遥测也有传感器误差，不应被当成绝对无误差的真值。

## 图形界面步骤

1. 运行 `launch_gui('zh')`。在“热网络”页填写自己设备的节点、热容、面积、光学参数、功耗和节点间热导，或读取已有设备配置。
2. 在“遥测与验证”页导入数据、确认列映射、单位及驱动方式。热功率模式要求每个节点有明确的外部吸收热功率，零值也需明确给出。
3. 打开“设备标定”页，从当前设备建立参数表。默认所有参数锁定。标称值来源于当前设备；要改设备本身，返回热网络页修改后重新建立参数表。
4. 只解锁少量有依据的参数。分别填写下界、上界、先验标准差、来源，以及“部件物理参数”或“模型等效参数”。下界、上界必须包住标称值；先验标准差必须为正。
5. 为每个完整日期指定“标定”“验证”“最终检查”或“排除”。至少各有一个标定日、验证日和最终检查日，且时间顺序不能交叉。不自动随机分割相邻采样点。
6. 填写测温不确定度及其依据、正则权重和可选的温度误差上限。确认设备参数依据、驱动独立性、检查数据未用于调参的历史；不能确认就保持未勾选，软件仍可分析，但不认定验收通过。
7. 执行标定，选择新的输出位置。检查参数表中的改变、贴边情况、每日温度误差及风险提示。中文和英文报告与图表一并导出。
8. 只有在复核后，才手动加载导出的标定设备继续仿真。加载配置不会证明其适用于未覆盖的季节、姿态、功耗或卫星。

## 参数范围怎样填

不要给所有参数统一套用“允许改变百分之十”。依据应来自材料、质量、图纸、测试记录、传感器规格或有说明的不确定性估计。

| 参数 | 建议处理 | 注意 |
|---|---|---|
| 质量和几何尺寸已知的热容 | 固定或限定在推导误差范围 | 热容由各部件质量与比热之积求和；本功能不同时自由估计质量、比热和热容 |
| 已测功耗 | 作为驱动，不再自由调整 | 映射了功耗遥测的节点不能同时标定常数功耗 |
| 接触热导 | 仅按有依据的范围调整 | 节点间连接代表的物理路径必须清楚 |
| 光学参数 | 有涂层依据时小范围调整 | 吸收率与发射率都必须位于零到一之间 |
| 等效节点参数 | 明确标注为模型等效参数 | 不得解释成某个元件、连接器的直接测量结果 |

例如热容标称值为 100 J/K、设备依据允许 90 至 110 J/K，就只填这个范围。
即使范围外的 45 J/K 能进一步降低误差，也不能采用。这个数字例子不是默认推荐范围。

“先验标准差”描述对标称值的可信程度，作用是惩罚不必要的偏移；它不是硬上下限，也不是标定后置信区间。
零标称值不显示相对百分比，查看绝对改变即可。参数锁定后始终保持标称值。

## 如何判读结果

- **在声明范围内满足判据**：所有预先指定的验证和检查日期、测温节点都满足用户误差上限，收敛和数值检查正常，没有贴边、明显不稳定或弱灵敏度等警告，且用户已确认必要依据。仍不等于物理模型得到普遍证明。
- **需要复核**：例如未填写验收上限、参数贴边、参数之间难以区分、依据未确认，或数据属于合成演示。温度误差低也不能跳过这些问题。
- **未满足误差判据**：至少一个预先指定的检查日期或节点超限。不要只看总体平均误差，也不要据此删除困难日期。
- **中止标定**：例如无有效数据、模型积分失败、参数范围无效或优化未收敛。没有得到有效冻结模型就不计算最终检查结果；已生成的协议和完成起点记录保留供排查。

软件计算的是“日期和节点等权的标准化均方误差＋参数偏移惩罚”，不是把所有密集遥测点当成独立样本的似然。
报告分别给出数据项和先验项。灵敏度检查不包含先验惩罚，以免把先验带来的唯一解误认为遥测确定了唯一物理参数。
目前不报告参数置信区间；灵敏度矩阵满秩也不能证明全局可辨识。

## 不插值与条件验证

所有原始行和历元均保留。时间、质量、驱动或已映射目标温度无效时拆段；孤立点不能形成仿真段。
缺测不补齐，目标不做偏置、比例或时间平移修正。有效相邻历元内驱动采用前值保持。
同一数据角色中连续有效的跨午夜记录连续积分；角色改变、缺测或超出最大时间间隔时重置。

默认用设备初始温度初始化。若明确启用了首个实测温度初始化，每段只使用起始温度，起始排除窗口仍生效，报告标记为条件验证；不会持续把目标测温喂回仿真。
以独立边界温度驱动得到的结果只能支持该边界条件下的部件响应，不能据此声称整个卫星热网络已验证。
直接复制目标温度作为驱动会被阻止；复杂的目标派生输入还需用户核查和声明。

## 输出文件

- `original_device.mat`：原始设备、场景和标称参数表。
- `calibrated_device.mat`：可供主界面手动加载的标定设备，同时保存原始依据和标定状态。
- `protocol_before_fit.mat`、`input_snapshot.mat`：标定前协议和完整输入快照。
- `frozen_before_checks.mat`：检查前冻结参数、权重、样本掩码、设置和训练灵敏度诊断。
- `calibration_result.mat`：完整结果，含原始与标定预测、逐角色比较及审计。
- `parameter_changes.csv`：全部固定和自由参数、标称值、范围、先验尺度、改变及贴边状态。
- `stage_metrics.csv`、`day_metrics.csv`、`scored_samples.csv`、`row_audit.csv`：阶段、逐日、逐样本、逐行记录。
- `check_numerics.csv`：冻结后的验证和最终检查弧段各自的实际步长减半检验；检查数据不参与参数更新。
- `report_zh.md`、`report_en.md`、`figures_zh`、`figures_en`：中英文报告和带图例的图表，不跨缺测连线。
- `artifact_manifest.csv`：文件长度与哈希。修改文件可通过重新校验发现，但这不是不可篡改签名。

为了安全地在电子表格软件中打开导出的逗号分隔表，可能被解释为公式的文本会加前导单引号；原始文本完整保留在数据快照和设备档案中。内部单位与变量标识保持规范形式，用户填写的名称与依据不会被自动翻译。

## 先试合成演示

```matlab
startup
addpath('examples')
run_device_calibration_demo
```

演示使用六个日期上的短热响应段，每个日期约八分钟，不是六个完整卫星日。
已知热容位于设备范围内时检查能否恢复；再把真值改到范围外，检查软件是否坚持原范围并诚实报告不通过。
这些数据由程序合成，仅检验软件机制，不能证明真实卫星温度已得到验证。

## 已有实测实验的限制

此前 MinXSS 简化板级实验得到的等效参数，不是该卫星热容、单个连接器热导的独立实测值。
本版本不会把那些拟合值包装成“真实设备参数”，也不会根据旧检查数据倒推出一套刚好能通过的新范围。
必须先有可对应到模型节点和传热路径的设备依据，才适合开展有说服力的设备参数约束实测验证。
