# 遥测导入与验证

适用版本：0.12.0。全部计算、导入、绘图和导出为MATLAB实现。

## 1. 从图形界面开始

1. 运行 `launch_gui('zh')`，在“热网络”页确认节点、热容、导热系数、表面积、光学参数和内部功耗。
2. 打开“遥测与验证”，选择使用方式，点击“导出空模板”。模板只有表头，不含虚构观测。
3. 导入CSV，在左侧表格逐列确认物理量、热节点和单位。非标准表头不会凭名称猜测单位。
4. 设置最大相邻间隔、积分最大子步长和每段起始排除时长，执行仿真或验证。
5. 通过节点下拉框查看仿真、测温及残差图，查看温度统计和逐行质量记录。
6. 导出到一个新的空目录。输出保留输入表、映射、模型、审计、误差、图表和说明报告。

“合成演示”按钮仅检查功能，预设的0.2 K误差不代表真实卫星精度。语言切换保留
当前映射和结果，图题、图例及报告使用所选语言。机器字段和原始传感器编号不翻译。

## 2. 选择正确的工作流

| 工作流 | 必需输入 | 可以验证什么 |
|---|---|---|
| 轨道遥测驱动 | 时间、位置、速度、同坐标系太阳位置 | 配有对应节点测温时，比较该轨道和姿态假设下的预测温度 |
| 热功率遥测驱动 | 时间、所有节点吸收的外部热功率 | 配有测温时，比较给定热输入下的热网络温度响应 |
| 验证已有单场景 | 已完成的单场景仿真、时间、对应节点测温 | 只比较完全相同的协调世界时历元，不重新求解或调整模型 |

只有轨道而没有测温时，可以做仿真，不能验证温度准确性。只有测温而没有驱动与
任务热参数时，可以做数据检查，不能据此重建完整热过程。

## 3. 数据格式与单位

输入文件为逗号分隔的CSV，也可通过接口传入MATLAB表。文件编码推荐UTF-8。
每列是一种标量观测，至少两行。时间必须唯一且递增，不自动排序或合并重复历元。

| 标准表头 | 含义 | 标准单位 |
|---|---|---|
| `epoch_utc` | 如 `2024-01-01T00:00:06.986915Z` | 明确的协调世界时，支持小数秒 |
| `quality` | 1为采用，其余值或缺失为拒绝 | 无量纲；未提供时不执行源质量标记筛选 |
| `x_eci_m`, `y_eci_m`, `z_eci_m` | 同一J2000地心惯性系位置 | 米 |
| `vx_eci_mps`, `vy_eci_mps`, `vz_eci_mps` | 同一坐标系速度 | 米/秒 |
| `sun_x_eci_m`, `sun_y_eci_m`, `sun_z_eci_m` | 同一坐标系太阳地心位置 | 米 |
| `eci_to_body_11` 至 `eci_to_body_33` | 惯性系向量到本体系的九个矩阵元素 | 无量纲 |
| `temperature_k_<节点名>` | 节点测温 | 开尔文 |
| `temperature_c_<节点名>` | 节点测温 | 摄氏度 |
| `external_power_w_<节点名>` | 节点已经吸收的外部热功率 | 瓦 |
| `internal_power_w_<节点名>` | 节点内部耗散热功率 | 瓦 |

非标准表头可手动映射；位置支持米或千米，速度支持米/秒或千米/秒，温度支持
开尔文或摄氏度。节点名必须来自当前热网络。传感器位置与热节点对应关系由任务
文档确定，不能按曲线相似程度随意分配。

轨道模式需确认坐标系。地固系、其他惯性系及其太阳星历须先在外部完成一致转换。
姿态矩阵要求正交且右手；未提供姿态时使用当前场景姿态假设并写入来源记录。
轨道模式不再接收外部热功率列，以避免重复计热。内部功耗列可覆盖网络对应节点。

热功率模式要求所有节点都有外部吸收热功率列，即使功率为零也明确填0。
太阳电池输出电功率、供电电压、热流密度不能直接当作节点吸收热功率。
热流密度需结合实际面积、方向及吸收率换算；内部电功耗也需明确耗散节点。

## 4. 缺测、断段和时间对齐

- 坏时间、源质量拒绝、无效驱动、非法姿态不参与仿真，保留原因。
- 无效行两侧分开计算；即使两侧时间差小于上限，也不跨越坏行连接。
- 相邻间隔大于上限时断段，每段至少两个样本；孤立点单列记录。
- 不插值或填补缺测。有效相邻时刻之间采用“区间起点热功率保持”的数值驱动假设；它不是在缺测段补数。
- 每段独立初始化，不做虚构的遥测周期预热。失败段整段标记，不只剔除误差大的点。
- 比较仅接受精确协调世界时匹配，不四舍五入、不最近邻匹配、不自动时间平移。

默认最大间隔为60秒，不适合所有仪器。某通道120秒采样时应依据原始采样规范
显式设置相应上限；不能通过放宽到数小时跨越真实缺测。

## 5. 避免验证信息泄漏

默认初始温度来自热网络，测温不参与驱动或拟合。勾选“以首个有效实测温度初始化”
后，各段映射节点的首温成为初始条件，报告标明为条件验证；未测节点仍用网络初温。
无论是否使用实测初始化，每段首样本和起始排除窗口均不参与打分。

默认排除600秒只是操作起点，不保证覆盖所有热时间常数。应依据独立热参数或事先
方案确定排除窗口，不能看完误差再挑有利窗口。短段被全部排除时会如实显示零配对。
用于热参数标定的数据不能再作为独立验证数据；建议以整日或完整工况划分。

## 6. 如何解释结果

残差为“预测减实测”，输出平均偏差、平均绝对误差、均方根误差、最大绝对误差和
相关系数。所有误差保留绝对水平，不拟合偏置、比例或相位。少于3个配对标记样本不足。
样本数不是独立实验次数；一分钟一次的同一条温度序列有自相关。

“用户误差上限”仅为用户判据，不是软件自动给出的物理有效性证明。误差小也可能
来自缓慢变化、强温控或参数标定；误差大需分别检查时间、单位、位置对应、输入和模型。
软件不会自动宣称跨卫星或跨季节验证成功。

导出目录主要包含：

- `telemetry_bundle.mat`：完整模型、原始表、映射、结果和验证报告。
- `input_data.csv`、`column_mapping.csv`：输入和映射。
- `import_audit.csv`、`simulation_audit.csv`、`segment_status.csv`：逐行及分段处理。
- `predicted_temperatures.csv`、`paired_samples.csv`、`temperature_metrics.csv`：预测、配对和误差。
- `temperature_comparison_*_zh.png` / `*_en.png`：有图例的逐节点图。
- `validation_summary_zh.md` / `validation_summary_en.md`、`manifest.json`：解释与来源。

## 7. 命令行示例

### 7.1 统一轨道/姿态/遥测任务包

`leotherm.importExternalTask` 支持 JSON、MAT 或等价 MATLAB 结构，唯一
接受的 schema 为 `leotherm.external_task.v1`。任务包显式声明 UTC 历元、
秒单位、ECI 位置/速度/太阳位置，以及可选的姿态。姿态可用
`ECI_TO_BODY_WXYZ` 四元数（标量在前）或方向余弦矩阵。四元数必须已经
归一化；非单位四元数、缺少单位/时间系统、乱序或重复历元均直接拒绝。
适配器返回可直接传给 `simulateTrajectory` 的 `task.trajectory`，并输出
`quality` 质量与同步报告。遥测历元只做精确 UTC 比较，不排序、不插值、
不最近邻匹配、不时间平移；不一致状态明确标记为
`mismatch_rejected_no_interpolation`。

```matlab
[task, quality] = leotherm.importExternalTask('mission_task.json', network);
trajectory = task.trajectory;
result = leotherm.simulateTrajectory(trajectory, scenario, network);
```

```matlab
startup
network = leotherm.defaultReceiverNetwork;
scenario = leotherm.defaultScenario;
mapping = leotherm.telemetryMapping(leotherm.readTelemetryTable('my_data.csv'), network);
% 审核mapping的source、target、node、unit四列后再运行。
data = leotherm.readTelemetry('my_data.csv', mapping, network);
options = leotherm.telemetryOptions(struct('mode','orbit','frame','J2000_ECI'));
result = leotherm.simulateTelemetry(data, scenario, network, options);
report = leotherm.validateTelemetry(result, data, options);
leotherm.writeTelemetryResults(result, report, data, 'results/my_telemetry_run', 'zh');
```

真实公开数据的下载、检查和当前限制见
[GRACE-FO案例](../studies/telemetry/README_CN.md)。该案例不把未确认位置的仪器
测温自动映射成默认GNSS节点。
