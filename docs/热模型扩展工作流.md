# 热模型扩展工作流（`leotherm.thermal_model.v1`）

本文面向第一次接入工程团队等效热模型的用户。它说明 JSON/MAT 交换适配器
实际检查什么、材料值如何追溯，以及哪些结论不能从“导入成功”推出。英文版见
[Thermal-model extensibility and exchange](thermal_model_extensibility.md)，最小的
合成 JSON 见 [`examples/projects/06_engineering_model_exchange.json`](../examples/projects/06_engineering_model_exchange.json)。

## 先区分两个接口

`leotherm.io.importThermalModel` / `exportThermalModel` 负责交换文件；
`leotherm.model.normalize` / `validate` 负责面向求解器的规范化模型。前者的顶层
字段是 `schema`、`metadata`、`nodes`、`materials`、`components`、`contacts`、
`boundaries`、`provenance`、`uncertainty`；后者包含 `network`、`geometry`、
`volumeMesh`、`material`、`units`、`connectivity`、`provenance`、`uncertainty`。
两套字段不能混用。适配器不会把部件自动写回网络，也不会根据名称猜测热参数。

## 交换文件契约

顶层 `schema` 必须严格等于 `leotherm.thermal_model.v1`。`metadata` 必须有非空
`modelId`、UTC 时间 `YYYY-MM-DDTHH:mm:ss[.fff]Z` 和以下 SI 单位：

| 字段 | 单位 |
|---|---|
| `length` | `m` |
| `mass` | `kg` |
| `time` | `s` |
| `temperature` | `K` |
| `power` | `W` |
| `heatCapacity` | `J/K` |
| `conductance` | `W/K` |
| `area` | `m^2` |

`nodes`、`materials`、`components`、`contacts`、`boundaries` 可以为空，但记录顺序
有工程含义，不会被排序、补齐、插值或删除。建议节点使用唯一 `id`、`name`、
`positionM`、`capacityJK`、`initialTemperatureK`、`internalPowerW`；接触、边界和部件
使用 `nodeIds` 引用节点。适配器只检查容器和数值是否为有限实数，不会补猜缺失物理量。
未认识的扩展字段会在 JSON 往返中保留。

MAT 文件应保存变量 `thermalModel`：

```matlab
thermalModel = myExchangeStruct;
leotherm.io.exportThermalModel(thermalModel, 'model.mat');
```

导入器也兼容变量名 `model`，或只有一个变量的旧 MAT 文件。JSON 与 MAT 都会先经
`leotherm.io.validateThermalModel` 完整校验，再返回模型；报告包含格式、schema、
输入字节指纹以及未知字段保留状态。这里的“完整校验”只表示交换数据满足
v1 数据契约，不表示材料、边界条件或温度结果已经通过物理验证、热真空相关或
飞行数据验证。

## 材料库：参考值不是任务实测值

`leotherm.materialLibrary()` 的内置值及其单位如下：

| id | 导热系数 W/(m·K) | 密度 kg/m³ | 比热 J/(kg·K) |
|---|---:|---:|---:|
| `aluminum_6061` | 167 | 2700 | 896 |
| `aluminum_7075` | 130 | 2810 | 960 |
| `stainless_steel_304` | 16.2 | 8000 | 500 |
| `peek` | 0.25 | 1320 | 1100 |

它们全部带有 `isReferenceValue=true`、`provenance='reference_only'`、来源说明和
示意性不确定度，**不是任何特定卫星的测量值**。任务分析应替换为可追溯的供应商
数据、材料试验、热真空结果或项目批准数据库记录。

自定义材料通过 `leotherm.materialLibrary('register', m)` 注册。必须提供非空
`id`、`name`、`source`、`confidence`、`uncertainty`；导热系数、密度、比热必须为正；
光学属性（如提供）必须在 `[0,1]`。温度相关材料可用 Kelvin 网格和正值曲线，也可
用 MATLAB `...Fcn`。函数句柄不能可靠地编码进 JSON；要跨团队交换请使用带来源和
温区的表格。曲线求值温度必须在 `temperatureRangeK` 内。

## 等效部件与节点映射

```matlab
c = leotherm.componentModel(spec);       % 校验/补齐部件
c = leotherm.componentModel(c, network); % 按 nodeName 或 nodeIndex 映射
```

部件需要 `id`、`name`、`source`、`confidence`、`uncertainty`，以及 `nodeIndex` 或
`nodeName`。热容二选一：直接给正的 `capacityJK`，或给 `massKg` 加材料（等效热容为
质量乘比热；温度相关材料在 293.15 K 取值）。`internalPowerW`、`contactConductanceWK`、
`projectedAreaM2`、`radiatingAreaM2` 不得为负；吸收率和发射率必须在 `[0,1]`。

映射结果含 `nodeIndex`、`nodeName` 和 `networkPatch`，但不会修改传入的网络。应由
工程人员审阅并显式应用 patch，再调用规范化和求解流程。

## 单位、来源、指纹和不确定度

在 `provenance.source` 写明数据集/文档编号、版本和日期；在
`provenance.transformations` 或扩展字段记录集总、舍入、降阶和单位换算。若存在
`provenance.inputFingerprint`，它表示上游源数据**原始字节**的 64 位 SHA-256 十六进制摘要；
它不是当前导出容器的摘要，因此不会阻断 MAT/JSON 往返。导入报告同时给出两个语义
不同的指纹：

| 字段 | 语义 | 用途 |
|---|---|---|
| `report.inputFingerprint` | 当前导入 JSON/MAT 容器的原始字节摘要 | 审计本次交换文件；重新格式化或保存后可能变化 |
| `report.sourceFingerprint` | `model.provenance.inputFingerprint` 声明的上游源数据摘要 | 追溯生成模型的源文件；上游不变时应保持不变 |

因此，`provenance.inputFingerprint` 既不是当前导出文件摘要，也不是物理正确性证明。
严格流程可使用
`leotherm.io.importThermalModel(path,'RequireFingerprint',true)`。

不要在声明 SI 的同时传入 mm、cm、摄氏度、小时或 `W/m^2`。程序不会自动换算、插值、
排序、补齐或删除记录；请在上游换算并留下记录。`uncertainty` 不得静默折算成确定值；
规范化模型 v1 的采样器仅支持 `stratified_uniform`。

## 当前不支持的功能

* 不直接读取任意热分析软件格式；需由团队编写明确的 JSON/MAT 转换层。
* 不从名称或几何自动推断接触、边界、连通性、材料分区或缺失参数。
* JSON 不交换 MATLAB 函数句柄，也不执行供应商脚本。
* 不自动把表面辐射接到体 FEM 网格，也不对非匹配网格偷偷插值。
* 不做热真空相关、传感器标定、鉴定裕度、冷热工况认证或在轨数据验证。

## 推荐交接步骤

1. 将团队降阶模型写入 v1 字段，并统一为上述 SI 单位。
2. 附上来源、版本、变换、置信度和不确定度；明确标记参考值。
3. 运行 `leotherm.io.validateThermalModel` 或 `importThermalModel`，逐项修复错误。
4. 将部件映射到现有网络，审阅 `networkPatch`，再用 `leotherm.model.normalize` 构造
   求解器模型。
5. 在工程决策前独立做连通性、能量守恒、敏感性和相关性检查。

“导入成功”只表示交换数据完整且符合格式，不等于该等效模型已经通过工程热控鉴定。
