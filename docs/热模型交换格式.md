# 热模型交换格式（`leotherm.thermal_model.v1`）

该格式用于工程模型在求解器、前处理和审计工具之间交换。文件扩展名为
`.json` 或 `.mat`；MAT 文件应包含变量 `thermalModel`。导入入口为
`leotherm.io.importThermalModel`，导出入口为 `leotherm.io.exportThermalModel`。

顶层必须包含以下字段：`schema`、`metadata`、`nodes`、`materials`、
`components`、`contacts`、`boundaries`、`provenance` 和 `uncertainty`。其中
`schema` 必须精确为 `leotherm.thermal_model.v1`。数组的顺序具有工程含义，
适配器不会排序、补齐、插值或删除记录。

`metadata` 至少包含 `modelId`、`createdUTC` 和 `units`。时间戳采用
`YYYY-MM-DDTHH:mm:ss[.fff]Z`（UTC）表示；单位字段必须声明 SI 基准：
`length=m`、`mass=kg`、`time=s`、`temperature=K`、`power=W`、
`heatCapacity=J/K`、`conductance=W/K`、`area=m^2`。

`nodes`、`materials`、`components`、`contacts` 和 `boundaries` 保持为记录数组
（也可为空）；记录中的工程字段由核心模型契约解释。推荐节点记录包含唯一 `id`
和三维 `positionM`，接触和边界通过 `nodeIds` 引用节点。适配器只做容器和数值
完整性检查，因此不会猜测缺失的物理参数。

`provenance` 用于可追溯性。若存在 `inputFingerprint`，其值表示模型进入本工作台
之前的源数据字节的 64 位 SHA-256 十六进制摘要；它不是当前导出文件的摘要，因此
带来源指纹的模型可以正常 MAT/JSON 往返。导入报告中的 `inputFingerprint` 是当前
文件字节摘要，`sourceFingerprint` 是模型声明的来源摘要。其它来源、变换、软件版本
和时间字段可按项目需要增加。`uncertainty` 保存不确定性范围、
分布、证据或假设；不得把不确定性静默折算为确定值。

两个指纹的语义必须保持区分：`report.inputFingerprint` 只审计本次导入的 JSON/MAT
容器原始字节，重新格式化或保存后可能变化；`report.sourceFingerprint` 追溯
`model.provenance.inputFingerprint` 声明的上游源文件，只要上游未变就应保持不变。
任一指纹都不是物理正确性、热真空相关、鉴定或飞行数据验证的证明；交换校验通过
仅说明数据满足 v1 完整性契约。

未知字段会随结构体/JSON 原样保留，便于前向兼容；未知字段中的非有限数值仍会
被拒绝。任何 schema、单位、UTC、数值或指纹错误均产生带有 `leotherm:` 前缀的
明确错误，不会返回部分模型。
