# 外部热结果交换（`leotherm.thermal_result.v1`）

本接口用于在外部热求解器与本项目之间交换**结果数据**。导入只负责结构与可追溯性检查；“导入成功”不等于物理验证通过，也不会替代求解器验证。

## 文件格式与调用

支持 MATLAB `MAT` 和 UTF‑8 `JSON`。MAT 文件应包含变量 `thermalResult`（或 `result`；仅有一个变量时可使用该变量）。

```matlab
[result, report] = leotherm.io.importThermalResult('run.json');
report = leotherm.io.validateThermalResult(result);
```

`report.inputFingerprint` 是输入文件原始字节的 SHA‑256。若提供 `provenance.inputFingerprint`，其值必须与该指纹一致；可用 `RequireFingerprint,true` 强制要求声明指纹。

## v1 结构

必需字段：

- `schema`: 固定为 `leotherm.thermal_result.v1`。
- `epochs`: ISO‑8601 UTC 文本数组，必须以 `Z` 结尾并严格递增。输入顺序就是语义顺序。
- `nodeIds`: 非空且唯一的节点 ID 数组。
- `units`: 结构体，`epoch='UTC'`；`temperatureK='K'`、`heatPowerW='W'` 与相应数据字段配套。
- `temperatureK` 和/或 `heatPowerW`: `numel(epochs) × numel(nodeIds)` 数值矩阵。至少提供一个。

可选字段：`modelFingerprint`、`provenance`、`qualityFlags`、`extensions` 以及供应方自定义字段。未知字段原样保留。

## 明确禁止的隐式行为

导入器和验证器均**不会**排序 epochs、插值、补齐缺失样本、时间偏移、摄氏/华氏到开尔文转换，或瓦特与其他功率单位换算。单位必须在文件中明确声明并使用上述规范单位。

## 缺失、坏数据与覆盖统计

`NaN` 样本计入 `report.missing`；`Inf` 或复数样本计入 `report.badData`。这些数据不会被删除或修复，`report.validationPassed` 仅在两者均为零时为真。报告同时给出 UTC 覆盖起止、逐段 `intervalSeconds` 及最小/最大/平均/中位间隔，便于下游审计。

推荐外部系统在 `qualityFlags` 或 `provenance` 中记录传感器状态、求解器版本、生成时间和转换链，但不得把这些元数据当作验证结论。
